# ScreenRest 상용 앱 수준 제품·디자인 개선 보고서

- 작성일: 2026-09-05
- 범위: Android 앱 정보 구조, 핵심 사용자 흐름, 디자인 시스템, 접근성, 태블릿 대응, 신뢰 형성 장치
- 검토 근거: 현재 Jetpack Compose 코드, 테마·타이포그래피, 차단 화면, 제품·안전 문서
- 시각 검토 상태: 최신 실행 화면 미확보. 연결 기기가 없었고 로컬 에뮬레이터는 Windows 권한 오류로 ADB에 연결되지 않았다. 따라서 아래 평가는 **구조와 구현 근거가 있는 제품 진단**이며, 색 대비·실제 여백·잘림·키보드·TalkBack 동작은 최신 스크린샷과 실기기 검증이 추가로 필요하다.

## 1. 결론

ScreenRest는 기능의 폭과 정책 안전성은 이미 일반적인 초기 MVP보다 강하다. 다섯 가지 정책, 고행 단계, 정책 충돌 설명, 부모 승인, 임시 허용, 실제 적용 결과, 안전 복구까지 한 제품 안에 들어 있다.

상용 앱 수준을 가로막는 핵심 문제는 기능 부족보다 **정보 구조와 표현 밀도**다. 현재 화면은 사용자용 웰빙 앱이라기보다 기능이 잘 갖춰진 관리 콘솔에 가깝다. 가장 먼저 해야 할 일은 기능을 더 추가하는 것이 아니라 다음 세 가지다.

1. 하단 내비게이션과 역할별 화면을 단순화한다.
2. 사용자가 지금 적용되는 결과와 다음 행동을 한눈에 알게 한다.
3. 디자인 토큰·접근성·적응형 레이아웃을 시스템으로 정리한다.

## 2. 현재 앱 구성

### 진입 흐름

1. 사용 시간 모니터링 고지와 동의
2. 관리 PIN 최초 설정
3. 사용 기록·다른 앱 위 표시·알림 권한 설정
4. 메인 화면 진입

### 현재 주요 내비게이션

- 개요
- 시간
- 차단
- 통계
- 안전
- 설정
- 하단 저장 상태/액션

휴대폰 하단에 실질적으로 일곱 개 조작 대상이 한 줄에 놓인다. Android 공식 가이드는 같은 계층의 하단 내비게이션 목적지를 3~5개로 권장한다.

### 기능 분류

- 시간 관리: 요일별, 앱 그룹, 앱별 제한
- 실행 범위 관리: 스케줄 차단, 허용앱만 모드
- 예외 관리: 제한 없음 앱, 임시 허용
- 통계: 오늘, 평균, 최고 사용일, 30일 추세, 상위 앱, 그룹
- 가족: 부모·자녀 역할, 연결 코드, 요청 승인·거절, 연결 기기
- 안전: Safe Mode, 정책 적용, 준비 상태, 진단, 안전 복구
- 차단 화면: 사유, 고행 단계, 시간 추가, 오늘만 허용, 부모 요청, Emergency Pass

## 3. 현재 강점

### 3.1 정책 결과를 설명하려는 구조가 있다

`앱별 실제 적용 결과`, 활성 실행 범위, 시간 제한 중 먼저 끝나는 정책, 제한 없음 앱을 별도로 계산한다. 복합 정책을 단순히 저장하는 데서 끝나지 않고 결과를 설명하려는 방향은 신뢰 형성에 매우 유리하다.

### 3.2 실수 방지 장치가 강하다

- 변경 사항을 즉시 적용하지 않고 Draft로 유지
- 저장 배너와 관리 PIN 확인
- 고행 3단계 다중 경고
- 잘못된 정책 조합 사전 경고
- 안전 복구와 Emergency Pass 분리

이 구조는 자녀 보호 앱에서 중요한 “잘못 저장해서 기기를 못 쓰는 상황”을 줄인다.

### 3.3 휴대폰과 태블릿을 함께 고려했다

폭 720dp 이상에서 두 열을 사용하는 `AdaptiveTwoPane`과 다이얼로그 최대 너비가 존재한다. 출발점은 좋다.

### 3.4 상태 색상과 문구를 함께 사용한다

정상·경고·초과를 색상만으로 표현하지 않고 배지와 텍스트를 같이 표시한다. 색각 이상 사용자를 위해 의미를 색 하나에만 의존하지 않는 방향이다.

### 3.5 차단 화면의 역할 분기가 구체적이다

부모 연결 여부, 고행 단계, 요청 상태, 임시 허용 종료, Emergency Pass 사용 가능 시각에 따라 행동을 나눈다. 제품 핵심 로직은 상용화 가능한 방향에 가깝다.

## 4. 가장 중요한 UX 위험

### P0-1. 하단 내비게이션이 과밀하다

현재 6개 화면 탭과 저장 액션을 같은 하단 바에 둔다. 작은 화면에서 라벨 생략, 오터치, 현재 위치 인식 저하가 발생하기 쉽다. 저장은 목적지가 아니라 현재 작업에 대한 행동이므로 내비게이션과 같은 자리에 두면 정보 구조가 흐려진다.

#### 권장 구조

휴대폰은 다음 5개로 정리한다.

1. `오늘`: 현재 상태, 사용량, 적용 정책, 다음 차단
2. `규칙`: 시간 제한과 실행 범위 설정
3. `통계`: 추세, 앱, 그룹
4. `가족`: 자녀 선택, 요청, 연결
5. `더보기`: 안전, 권한, PIN, 알림, 언어, 진단

저장은 탭에서 제거하고 현재처럼 변경이 있을 때만 나타나는 하단 저장 배너를 유지한다. 태블릿에서는 같은 목적지를 왼쪽 Navigation Rail로 바꾼다.

### P0-2. 부모와 자녀에게 같은 정보 구조를 제공한다

부모는 여러 자녀의 상태와 요청 처리가 중요하고, 자녀는 자신의 남은 시간·현재 제한·요청 결과가 중요하다. 동일한 탭과 설정 밀도를 제공하면 양쪽 모두 불필요한 정보를 보게 된다.

#### 권장 구조

- 부모 홈: 자녀 선택 → 현재 상태 → 요청 → 빠른 조정 → 상세 규칙
- 자녀 홈: 남은 시간 → 현재 적용 규칙 → 요청 상태 → 허용 앱
- 독립 사용: 오늘 상태 → 규칙 → 통계

역할 변경은 설정에 남기되, 역할별 홈과 기본 CTA는 분리한다.

### P0-3. 현재 결과보다 설정 구조가 먼저 보인다

사용자는 정책의 우선순위를 배우고 싶어 하지 않는다. “이 앱이 지금 열리는가”, “얼마나 남았는가”, “왜 막히는가”가 먼저 보여야 한다.

#### 권장 구조

모든 규칙 화면 상단에 한 개의 고정된 `현재 적용 결과` 요약을 둔다.

- 현재 실행 범위: 일반 / 허용앱만 / 스케줄 이름
- 다음 상태 변경: 오후 9:00 스케줄 종료
- 가장 먼저 끝나는 시간 제한: YouTube 12분 남음
- 충돌 또는 무효 설정: 2개, `확인` 버튼

상세 앱 목록은 지금 구현된 필터 Bottom Sheet로 유지한다. 다만 사용자가 정책을 변경하면 결과 요약도 같은 화면에서 즉시 갱신되어야 한다.

### P0-4. 온보딩이 고지와 권한 목록 중심이다

현재 진입 흐름은 법적 고지 → PIN → 권한 다이얼로그다. 필요한 내용은 포함되어 있지만 사용자가 얻는 결과보다 앱이 요구하는 권한이 앞에 온다.

#### 권장 흐름

1. `어떻게 사용할까요?` — 부모 / 자녀 / 내 기기
2. `무엇을 관리할까요?` — 하루 시간 / 특정 앱 / 집중 시간
3. 관리 PIN 설정
4. 권한을 하나씩 요청하며 해당 권한이 필요한 화면을 짧게 보여줌
5. 첫 규칙 만들기
6. `설정 완료` — 실제 차단 테스트 버튼 제공

모니터링 고지는 유지하되, 긴 문단 하나 대신 핵심 요약과 `자세히`로 나눈다. 부모·자녀 연결을 선택하지 않은 사용자에게 Firebase 관련 설명을 동일한 비중으로 노출할 필요는 없다.

### P0-5. 신뢰 상태가 여러 화면에 분산돼 있다

권한, 감시 서비스, 데이터 최신성, 동기화, 정책 적용 상태가 안전 탭과 개요, 설정에 흩어져 있다. 오류가 생겼을 때 사용자는 어느 화면을 봐야 하는지 모를 수 있다.

#### 권장 구조

오늘 화면 상단에 한 줄 상태를 둔다.

- `정상 작동 중 · 1분 전 확인`
- `설정 필요 · 사용 기록 권한 꺼짐`
- `동기화 지연 · 다시 시도`

누르면 문제 해결 화면으로 이동한다. 내부 패키지명, Worker, Foreground Service 같은 개발자 용어는 숨기고 `진단 정보 복사`에서만 제공한다.

## 5. 시각 디자인 개선

### P1-1. 카드 사용량을 줄인다

현재 거의 모든 단위를 둥근 카드로 감싸고 카드 안에 다시 상태 박스와 버튼을 넣는다. 화면 경계가 많아져 중요한 카드가 무엇인지 구별하기 어렵다.

#### 권장 원칙

- 한 화면의 큰 카드 1~2개만 강조
- 같은 성격의 설정은 구분선 기반 리스트로 통합
- 경고와 선택 상태에만 배경색 사용
- 단순 설명은 카드 밖 보조 텍스트로 배치

### P1-2. 타이포그래피 크기를 다시 올린다

현재 기본 `bodyMedium`은 13sp, `labelMedium`은 11sp, `labelSmall`은 10sp다. 정보가 많은 화면에서 작은 글씨로 밀도를 해결하면 가독성과 신뢰도가 떨어진다.

#### 권장 토큰

- 화면 제목: 24~28sp / Bold
- 섹션 제목: 18~20sp / SemiBold
- 주요 본문: 15~16sp
- 보조 본문: 13~14sp
- 배지·라벨: 최소 12sp
- 숫자 사용량: tabular numeral 유지

텍스트를 줄여 공간을 확보하고 글씨 크기를 유지하는 방향이 적절하다.

### P1-3. 한글 화면의 영문 상태를 정리한다

현재 `SAFE`, `LIVE`, `Warning`, `Exceeded`, `Emergency Pass` 등 영문 용어가 한글 문장과 섞인다. Emergency Pass처럼 제품 고유 명칭을 유지하더라도 첫 노출에는 `긴급 사용권(Emergency Pass)`처럼 의미를 함께 제공해야 한다.

권장 예시:

- SAFE → 안전 모드
- LIVE → 차단 적용 중
- Warning → 곧 제한
- Exceeded → 초과
- Emergency Pass → 긴급 사용권 · 7일 1회

### P1-4. 페이지별 제목과 핵심 행동을 제공한다

모든 탭 상단에 앱 이름과 동일한 부제목을 반복하기보다 현재 페이지의 목적을 표시한다.

- 오늘: `오늘의 사용`
- 규칙: `사용 규칙`
- 통계: `사용 흐름`
- 가족: 선택한 자녀 이름
- 더보기: `설정 및 안전`

### P1-5. 빈 상태와 완료 상태를 제품 경험으로 만든다

상용 앱에서는 데이터가 없을 때도 다음 행동이 분명해야 한다.

- 규칙 없음: `첫 사용 규칙 만들기`
- 연결된 자녀 없음: `자녀 기기 연결`
- 승인 요청 없음: `새 요청이 없습니다`
- 통계 부족: `사용 기록이 쌓이면 7일 비교가 표시됩니다`
- 권한 완료: 체크 아이콘과 `보호 준비 완료`

## 6. 접근성 위험

### P0 접근성

1. 도움말 버튼 등 일부 조작 요소의 표시 크기가 34dp다. 실제 터치 영역도 48dp 이상인지 보장해야 한다.
2. `PinVisibilityToggleButton`은 40dp, 일부 직접 입력 컨트롤은 36~44dp 높이다. 최소 터치 영역을 공통 컴포넌트에서 강제해야 한다.
3. 커스텀 Canvas 기반 진행률·탭 아이콘·검색 아이콘은 상태와 역할을 전달하는 semantics가 부족할 가능성이 있다.
4. 저장 배너와 오류 상태가 시각적으로만 바뀌면 TalkBack 사용자가 변화를 놓칠 수 있다. 오류에는 `error`, 중요 상태에는 `liveRegion`, 진행률에는 `progressBarRangeInfo`를 적용한다.
5. `maxLines = 1`과 말줄임이 광범위하다. 큰 글꼴, 한국어 긴 앱 이름, 독일어·영어 번역에서 핵심 행동이 잘릴 가능성이 크다.
6. 저장 버튼의 반복 점멸 애니메이션은 주의를 과도하게 빼앗을 수 있다. 시스템 애니메이션 축소 설정을 존중하고 한 번의 상태 전환으로 충분히 강조한다.

Android는 상호작용 요소에 최소 48×48dp 터치 영역을 권장하고, 커스텀 Compose UI에는 상태·오류·진행률 semantics를 제공하도록 안내한다.

## 7. 태블릿·폴더블 개선

현재 `maxWidth >= 720.dp`에서 두 열로 전환하는 것은 좋은 시작이지만 상용 태블릿 경험에는 다음이 더 필요하다.

1. 실제 Window Size Class 사용
2. 태블릿에서 하단 바를 Navigation Rail로 전환
3. 앱 목록과 상세 설정을 List–Detail Pane으로 분리
4. Bottom Sheet와 입력 필드의 최대 너비 제한
5. 세로·가로·분할 화면 전환 시 선택 탭, 스크롤, 입력값 유지
6. 마우스·키보드 포커스 상태와 Enter/Escape 동작

현재 선택 탭은 `remember`로만 저장되어 구성 변경 시 개요로 돌아갈 수 있다. 최소한 `rememberSaveable` 또는 Navigation Compose 상태로 옮겨야 한다.

## 8. 기능 완성도 개선

### P0. 사용자용 상태 설명

- 정책마다 `현재 적용됨 / 예약됨 / 비활성 / 고행 잠금` 상태 통일
- 앱 차단 이유에서 정책 이름과 종료 시각 제공
- 오래된 사용량에는 `업데이트 필요` 표시
- 부모 요청은 `전송 중 → 전달됨 → 확인함 → 승인/거절` 단계 표시
- 네트워크 오류와 권한 오류를 구분하고 사용자 행동을 제시

### P1. 부모 경험

- 여러 자녀가 연결되면 홈에서 자녀 전환
- 자녀별 현재 상태와 마지막 동기화 시각
- 요청 승인 시 결과 미리보기: `YouTube +15분, 오늘 총 45분`
- 승인·거절 기록과 누가 처리했는지 표시
- 연결 해제, 기기 교체, 토큰 만료에 대한 복구 흐름

### P1. 규칙 생성 방식

현재 다섯 정책을 그대로 유지하되 두 질문으로 안내한다.

1. `어떤 앱을 지금 실행할 수 있나요?` — 일반 / 허용앱만 / 스케줄
2. `실행 가능한 앱을 얼마나 쓸 수 있나요?` — 요일 / 그룹 / 앱별

고급 사용자는 상세 편집을 사용하고, 처음 사용자는 목적 기반 템플릿을 사용한다.

- 취침 준비
- 공부 시간
- 주말 게임
- 특정 앱 30분
- 하루 총 2시간

### P1. 통계의 의미 강화

숫자 나열보다 의사결정을 돕는다.

- 지난주 대비 증감
- 목표 대비 사용량
- 가장 자주 초과한 규칙
- 부모가 추가한 시간과 원래 사용 시간 분리
- 통계가 불완전한 날 표시
- 집계 기준과 제한 집계 제외 앱을 한 번에 설명

### P1. 출시 지원 기능

- 앱 안 개인정보·데이터 삭제 화면
- 진단 정보 복사 및 문의 연결
- 앱 버전·정책 버전·마지막 동기화 표시
- 장애 시 안전 복구 가이드
- 역할별 도움말
- 계정 및 연결 복구 시나리오

자녀 대상 또는 자녀를 포함한 앱은 Play Console의 대상 연령, Data Safety, 개인정보처리방침, SDK 사용 내용을 실제 동작과 정확히 맞춰야 한다. 모니터링 앱은 명확한 고지와 동의가 특히 중요하다.

## 9. 기술·디자인 시스템 정리

## 11. 단계별 건강 상태

1. 온보딩 — **개선 필요**: 필수 고지는 충실하지만 권한 중심이고 첫 성공 경험이 늦다.
2. 오늘/개요 — **보통**: 사용량과 정책 상태가 있으나 사용자용 핵심 상태와 개발자 상태가 섞인다.
3. 시간 규칙 — **좋음, 과밀함**: 기능과 충돌 방지는 강하지만 한 화면에서 배우기 어렵다.
4. 차단 규칙 — **좋음, 과밀함**: 스케줄·허용앱·예외 관계가 정교하지만 현재 결과를 먼저 보여줄 필요가 있다.
5. 통계 — **보통**: 기본 지표는 충분하나 비교·불완전 데이터·추가 시간의 의미가 약하다.
6. 가족 관리 — **개선 필요**: 기능은 많지만 역할별 홈과 자녀 중심 탐색이 없다.
7. 안전/설정 — **구조 변경 필요**: 안전성은 강하지만 개발·진단 성격이 주요 탭을 차지한다.
8. 블록 화면 — **논리적으로 좋음, 시각 검증 필요**: 단계별 행동은 명확해졌지만 최신 폰·태블릿 캡처가 필요하다.
