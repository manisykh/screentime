# ScreenRest 2번 디자인 시안 구현 전환 계획

- 작성일: 2026-09-07
- 선택 시안: `docs/design/screenrest-option-2-family-rhythm.png`
- 대상: 부모 기기의 `오늘/개요` 화면을 시작으로 한 전체 UI 체계 개선
- 최우선 원칙: 정책 판단·차단·고행·부모 승인 로직은 유지하고, 화면과 화면용 데이터 조립 계층을 분리하여 교체한다.

## 1. 결론

2번 시안은 단순한 색상 변경이 아니다. 현재의 `상태 카드 + 정책 요약 + 사용 앱 목록` 구조를 부모가 하루의 흐름을 이해하는 구조로 바꾸는 작업이다.

핵심 변화는 다음 세 가지다.

1. 숫자와 정책 목록보다 `지금 어떤 시간인지`를 먼저 보여준다.
2. 사용량, 다음 일정, 부모 요청을 한 화면에서 우선순위에 따라 보여준다.
3. 시간·차단·안전·설정으로 나뉜 현재 탐색 구조를 사용자 관점의 `오늘·규칙·통계·가족·더보기`로 정리한다.

구현은 한 번에 전체 화면을 갈아엎지 않는다. 먼저 기존 데이터로 새 `오늘` 화면을 만들고, 기능 동등성이 확인된 뒤 탐색 구조와 나머지 화면을 차례로 옮겨야 한다.

## 2. 시안에서 반드시 보존할 핵심 경험

### 화면 첫 인상

- 상단에서 현재 선택한 자녀를 즉시 확인한다.
- 가장 큰 문구로 현재 상태를 알린다.
  - 예: `지금은 자유 시간이에요`
  - 예: `집중 시간이 적용 중이에요`
  - 예: `오늘 사용 시간이 끝났어요`
- 다음 변화의 시각을 한 문장으로 안내한다.
  - 예: `오후 9시에 집중 시간이 시작됩니다`

### 하루 흐름

- 시간표를 단순 장식으로 만들지 않는다.
- 현재 시각, 활성 스케줄, 다음 스케줄을 실제 정책 데이터에서 계산한다.
- 스케줄이 없으면 억지로 `등교·자유 시간·취침`을 만들지 않고 `오늘 예약된 집중 시간이 없습니다`로 대체한다.

### 사용량

- `사용한 시간`과 `남은 시간`을 함께 표시한다.
- 일일 제한이 꺼져 있으면 남은 시간을 가짜로 계산하지 않고 `오늘 42분 사용`으로 표시한다.
- 추가 시간과 오늘만 해제가 적용됐으면 원래 한도와 구분해서 알린다.

### 부모 요청

- 부모 기기이며 활성 Pending 요청이 있을 때만 노출한다.
- 동일 자녀·동일 대상 요청이 여러 개면 현재 정책대로 가장 최근 요청만 대표로 보여준다.
- 카드의 `요청 보기`는 바로 승인하지 않고 상세 검토 화면을 연다.

## 3. 현재 코드와 새 화면의 연결 관계

| 새 화면 요소 | 현재 데이터 원천 | 구현 방식 |
|---|---|---|
| 자녀 이름·선택 | `ParentManagementState.linkedChildDevices`, `childDeviceName` | 현재 선택 자녀 ID를 별도 화면 상태로 관리 |
| 현재 상태 문구 | `PolicySummary.activeScheduleSummary`, `allowOnlyModeEnabled`, `totalStatus` | 우선순위 기반 순수 함수로 문구 생성 |
| 다음 일정 | `PolicySummary.nextScheduleSummary` | 시작 시각과 날짜 경계까지 계산 |
| 사용·남은 시간 | `actualTotalUsedMinutes`, `totalUsedMinutes`, `totalLimitMinutes`, `totalExtraMinutes` | 집계값과 차단용 보정값을 혼동하지 않도록 구분 |
| 오늘의 흐름 | 활성화된 `scheduleSummaries` | 비활성 스케줄 제외 후 시간순 정렬 |
| 추가 시간 요청 | `ParentManagementState.remoteUnlockRequests` | Pending·미만료 요청 중 최신 1개 표시 |
| 오늘의 규칙 | `PolicySummary` | 활성 정책만 2~3개로 축약하고 상세 화면 연결 |
| 앱 사용 목록 | `SafeModeUiState.todayUsage` | 상위 3개만 노출, 전체는 통계 탭에서 확인 |
| 업데이트 상태 | `usageLastUpdatedAtMillis`, `lastSyncMillis` | 오래된 데이터일 때만 상태 경고 표시 |

현재 `OverviewContent`는 `StatusCard`, `PolicySummarySection`, `UsageStatsSection`을 순서대로 조합한다. 이 구조를 바로 수정하기보다 새 `TodayScreen`을 만들고 기존 Overview 경로에서 교체하는 것이 안전하다.

## 5. 단계별 구현 프로세스

### 0단계: 동작 기준선 고정

목적은 디자인 작업 중 기존 기능이 바뀌었는지 판단할 기준을 만드는 것이다.

- 부모·자녀·독립 기기의 현재 개요 화면을 캡처한다.
- 다음 상태를 각각 기록한다.
  - 일일 제한 켜짐/꺼짐
  - 활성 스케줄 있음/없음
  - 허용앱만 켜짐/꺼짐
  - 부모 요청 있음/없음
  - 오프라인 및 오래된 사용량
  - 고행 단계 활성 상태
- 현재 각 카드가 사용하는 값과 클릭 결과를 표로 남긴다.
- 이 단계에서는 정책 계산 코드나 저장소를 변경하지 않는다.

완료 조건: 새 화면과 비교할 수 있는 상태별 기준 자료가 존재한다.

### 1단계: 디자인 토큰 확정

기존 색상은 2번 시안과 상당 부분 호환된다. `RestNight`, `RestBlue`, `RestMint`, `RestMoon`, `RestCream`을 유지하되 화면에서 직접 색을 만들지 않게 정리한다.

권장 역할 토큰:

- `BrandPrimary`: 주요 버튼과 현재 위치
- `StateSafe`: 정상·사용 가능
- `StateScheduled`: 예정된 집중 시간
- `StateWarning`: 남은 시간이 적음·요청 대기
- `StateBlocked`: 차단·거절·위험
- `SurfaceWarm`: 2번 시안의 따뜻한 기본 배경
- `SurfaceCool`: 현재 상태 강조 영역

타이포그래피는 다음을 기준으로 한다.

- 현재 상태: 26~30sp, Bold
- 남은 시간: 24~28sp, Bold, tabular numeral
- 섹션 제목: 18~20sp, SemiBold
- 본문: 15~16sp
- 보조 문구: 13~14sp
- 배지 및 하단 탭: 최소 12sp

완료 조건: 오늘 화면에 임의 `Color(...)`, 임의 폰트 크기, 화면별 다른 반경이 남지 않는다.

### 2단계: 화면 전용 상태 모델 추가

UI가 `SafeModeUiState` 전체를 직접 해석하지 않도록 `TodayUiState`를 만든다.

```kotlin
data class TodayUiState(
    val role: DeviceRoleUi,
    val selectedChild: ChildUi?,
    val currentPhase: CurrentPhaseUi,
    val timeline: List<TimelineItemUi>,
    val usageBudget: UsageBudgetUi,
    val pendingRequest: ParentRequestUi?,
    val activeRules: List<ActiveRuleUi>,
    val topApps: List<AppUsageUi>,
    val freshness: DataFreshnessUi,
)
```

`TodayUiMapper`는 기존 정책 결과를 읽기만 하며 다음을 새로 판단하지 않는다.

- 실제 차단 여부
- 앱 우선순위
- 고행 해제 가능 여부
- Emergency Pass 사용 가능 여부

이 값들은 반드시 기존 저장소와 정책 엔진의 결과를 그대로 사용해야 한다. Mapper는 화면에 맞게 축약하고 정렬하는 역할만 담당한다.

완료 조건: 동일 입력으로 항상 동일한 현재 문구·타임라인·남은 시간이 생성되는 단위 테스트가 있다.

### 3단계: 새 오늘 화면을 독립적으로 구현

구현 순서는 다음과 같다.

1. `TodayHeader`
   - 앱 이름
   - 선택 자녀
   - 자녀 전환 버튼
2. `CurrentPhaseHero`
   - 현재 상태
   - 다음 변화
   - 활성/차단/경고 상태 색상
3. `DayTimeline`
   - 활성화된 스케줄만 표시
   - 현재 위치 표시
   - 자정 넘김 스케줄 처리
4. `UsageBudgetCard`
   - 실제 사용 시간
   - 총 허용 시간
   - 추가 시간
   - 제한 없음 상태
5. `ParentRequestCard`
   - 최신 Pending 요청
   - 요청 상세 화면으로 이동
6. `TodayRulesList`
   - 활성 규칙 2개 우선 노출
   - 전체 규칙 화면으로 이동

첫 구현에서는 기존 하단 탭과 화면 라우팅을 유지한 채 `OverviewContent`만 새 화면으로 교체한다. 이 방식으로 정책 설정 화면과 저장 과정의 회귀를 차단한다.

완료 조건: 기존 개요 화면이 제공하던 핵심 상태가 새 화면에서도 빠짐없이 확인된다.

### 4단계: 역할별 오늘 화면 분기

2번 시안은 부모 화면이다. 자녀와 독립 사용 기기에 그대로 적용하면 부자연스럽다.

#### 부모 기기

- 선택한 자녀의 상태
- 다음 집중 시간
- 부모 요청
- 원격 상태의 마지막 동기화 시각

#### 자녀 기기

- 본인의 남은 시간
- 현재 차단 또는 허용 상태
- 다음 차단 시각
- 부모 요청 전송 상태
- 부모용 승인 버튼은 절대 노출하지 않음

#### 연결 없는 개인 기기

- 자녀 선택 영역 제거
- 오늘 사용량과 현재 규칙 중심
- 가족 요청 영역 제거

완료 조건: 역할에 맞지 않는 CTA와 설명이 보이지 않는다.

### 5단계: 부모 요청 상세 흐름 연결

오늘 화면에서 요청을 바로 승인하게 만들지 않는다.

권장 흐름:

1. `10분 더 사용하고 싶어요` 카드 선택
2. 요청 상세 Bottom Sheet 표시
3. 대상 앱·현재 사용량·현재 제한·요청 시간 확인
4. `시간 추가`, `오늘만 허용`, `거절` 중 선택
5. 기존 승인·거절 ViewModel 함수를 호출
6. 처리 중/완료/실패 상태 표시
7. 완료된 요청은 오늘 카드에서 제거

현재 `RemoteUnlockRequestRow`에 있는 시간 선택과 승인·거절 동작을 공통 요청 상세 컴포넌트로 추출해 재사용한다.

완료 조건: 오늘 화면과 가족 화면 어디서 처리해도 동일한 요청 상태와 알림 정리 결과가 나온다.

### 6단계: 하단 탐색을 5개로 이전

선택 시안의 하단 메뉴는 다음과 같이 매핑한다.

| 새 메뉴 | 기존 화면 |
|---|---|
| 오늘 | Overview |
| 규칙 | Time + Blocking |
| 통계 | Stats |
| 가족 | Settings 안 ParentManagement |
| 더보기 | Safety + 나머지 Settings |

`규칙` 안에서는 상단 세그먼트나 화면 내 섹션으로 다음 두 묶음을 구분한다.

- 시간 제한: 요일별, 앱 그룹, 앱별
- 실행 범위: 스케줄, 허용앱만, 제한 없는 앱

저장은 탐색 목적지가 아니므로 하단 탭에서 제거하고, 변경이 생겼을 때만 나타나는 기존 저장 배너를 유지한다.

탐색 이전은 오늘 화면이 안정된 뒤 수행한다. 동시에 진행하면 문제가 UI 때문인지 라우팅 때문인지 구분하기 어렵다.

완료 조건: 기존 6개 화면의 모든 진입점이 새 5개 목적지 안에서 발견 가능하며, 뒤로 가기와 화면 상태가 정상 동작한다.

### 7단계: 일러스트 자산 제작

2번 시안의 분위기를 살리려면 다음 상태 자산이 필요하다.

- 자유 시간
- 집중 시간
- 차단됨
- 취침 또는 일정 종료
- 빈 요청/연결 없음 상태

생성 시안의 일러스트를 그대로 잘라 쓰지 않는다. 각 자산을 독립 이미지로 제작하고 다음 기준으로 검수한다.

- 앱 아이콘의 기존 세계관과 일치
- 동일한 조명·선명도·시점
- 밝은 배경과 어두운 배경 모두에서 식별 가능
- 글자나 숫자를 이미지 안에 포함하지 않음
- WebP 또는 적절한 Android 리소스로 최적화
- 장식 이미지는 TalkBack에서 읽지 않도록 처리

일러스트가 준비되기 전에는 기존 앱 아이콘과 Material 아이콘만으로 기능 구현을 완료할 수 있어야 한다.

완료 조건: 일러스트가 없어도 기능과 정보 전달이 완전하며, 추가 시 성능과 접근성을 해치지 않는다.

### 8단계: 태블릿·가로 화면 대응

휴대폰 시안을 단순 확대하지 않는다.

- Compact: 선택 시안과 같은 단일 세로 흐름
- Medium: 상단 상태와 타임라인은 전체 너비, 하단은 사용량/규칙 2열
- Expanded: 왼쪽 Navigation Rail, 가운데 오늘 상태, 오른쪽 요청·규칙 보조 패널

폭 720dp 직접 비교 대신 Window Size Class 기반 전환을 권장한다. 회전 후에도 선택 자녀, 탭, 스크롤 위치가 유지되어야 한다.

완료 조건: 휴대폰·태블릿·분할 화면에서 잘림과 과도한 빈 공간이 없다.

### 9단계: 접근성과 상태 표현

- 모든 터치 영역 최소 48dp
- 타임라인 현재 상태에 `selected` 또는 상태 설명 semantics 제공
- 사용량 진행률에 `progressBarRangeInfo` 제공
- 요청 도착·처리 완료·동기화 실패에 `liveRegion` 적용
- 색상만으로 정상/예정/차단을 구분하지 않고 아이콘과 문구 병행
- 글꼴 200%에서 버튼과 핵심 문구가 잘리지 않게 최대 줄 수 설정
- 애니메이션 축소 설정을 존중하고 반복 점멸 사용 금지

완료 조건: TalkBack 탐색 순서가 시각적 순서와 같고, 큰 글꼴에서도 핵심 행동이 유지된다.

### 10단계: 점진적 전환과 정리

1. 새 오늘 화면을 내부 플래그로 연결
2. 부모 기기부터 기능 동등성 확인
3. 자녀·개인 기기 분기 확인
4. 새 5개 탐색 구조 적용
5. 기존 Overview 컴포넌트 제거
6. 공통 컴포넌트와 문자열을 새 구조로 이동
7. 사용하지 않는 카드와 중복 표시 로직 정리

완료 조건: 새 화면이 안정된 뒤에만 기존 코드를 삭제하며, 중간 단계에서도 앱이 동작한다.

## 6. 절대 같이 바꾸지 말아야 할 영역

디자인 전환과 동시에 다음을 재작성하면 위험이 급격히 커진다.

- 사용 시간 집계 알고리즘
- 실제 앱 차단 우선순위
- 고행 단계 시작·종료 규칙
- 부모·자녀 연결 데이터 구조
- FCM 및 Firestore 요청 전송 형식
- Emergency Pass 저장 및 갱신 정책
- 관리 PIN 검증 방식

이 영역은 새 UI가 기존 공개 함수와 상태를 호출하는 방식으로 연결한다. 필요한 데이터가 하나 부족하더라도 먼저 ViewModel의 표시용 상태를 확장하고, 핵심 정책 엔진을 UI 편의 때문에 변경하지 않는다.

## 7. 주요 위험과 방지책

### 위험 1: 시안의 시간표가 실제 정책과 달라짐

- 방지: 활성화된 스케줄만 사용하고, 비활성·요일 불일치 스케줄은 타임라인에서 제외한다.
- 자정 넘김, 겹치는 스케줄, 현재 스케줄 없음 테스트를 추가한다.

### 위험 2: 남은 시간이 실제 차단 기준과 달라짐

- 방지: `actualTotalUsedMinutes`는 통계 표시, `totalUsedMinutes`는 정책 판단 용도로 의미를 명시한다.
- 추가 시간과 오늘만 해제를 별도 표시 모델로 전달한다.

### 위험 3: 부모가 다른 자녀의 요청을 처리함

- 방지: 화면의 선택 자녀 ID와 요청의 childDeviceId를 항상 함께 검증한다.
- 자녀 전환 시 요청 카드와 사용량을 하나의 상태로 동시에 교체한다.

### 위험 4: 정보가 다시 과밀해짐

- 방지: 오늘 화면은 활성 규칙 최대 2개, 사용 앱 최대 3개, 요청 최대 1개만 노출한다.
- 나머지는 규칙·통계·가족 화면으로 이동한다.

### 위험 5: 새 5개 탭 전환으로 기능을 찾기 어려움

- 방지: 기존 기능별 이동표를 만들고 모든 진입점에 UI 테스트를 추가한다.
- 첫 업데이트에서는 변경된 위치를 한 번만 안내한다.

## 9. 권장 작업 단위

### 1차 작업: 오늘 화면의 뼈대

- 디자인 토큰
- `TodayUiState`와 Mapper
- 부모용 헤더·현재 상태·사용량
- 기존 Overview 경로 연결

### 2차 작업: 동적 흐름

- 실제 스케줄 타임라인
- 최신 부모 요청 카드
- 요청 상세 Bottom Sheet
- 오래된 데이터/오프라인 상태

### 3차 작업: 역할·탐색

- 부모/자녀/독립 화면 분기
- 5개 하단 탐색 구조
- 가족과 더보기 화면 분리

### 4차 작업: 마감 품질

- 독립 일러스트 자산
- 태블릿·폴더블
- 접근성
- 애니메이션과 빈 상태
- 기존 UI 제거

각 작업 단위가 끝날 때마다 컴파일과 장시간 검증은 사용자가 직접 수행하고, 구현 측에서는 짧은 정적 점검과 단위 테스트 범위를 명시한다.

## 10. 최종 완료 기준

- 첫 화면에서 3초 안에 현재 상태, 남은 시간, 다음 일정을 이해할 수 있다.
- 부모 요청이 있으면 스크롤 없이 발견할 수 있다.
- 활성화되지 않은 정책이 현재 상태나 타임라인에 표시되지 않는다.
- 사용량과 차단 판단 시간이 서로 다른 의미로 잘못 표시되지 않는다.
- 부모·자녀·독립 기기에서 역할에 맞는 정보와 CTA만 보인다.
- 기존 차단, 고행, PIN, Emergency Pass, 부모 승인 동작이 변하지 않는다.
- 200% 글꼴, TalkBack, 휴대폰, 태블릿에서 핵심 기능을 사용할 수 있다.
- 기존 6개 탭의 모든 기능이 새 5개 목적지 안에 빠짐없이 존재한다.

## 11. 권장 시작점

첫 구현은 `디자인 토큰 + TodayUiState + 부모용 TodayScreen`까지만 진행하는 것이 가장 안전하다. 여기서 실제 정책 데이터가 시안에 정확히 매핑되는지 확인한 뒤, 타임라인·요청 처리·탐색 구조를 순차적으로 추가한다.
