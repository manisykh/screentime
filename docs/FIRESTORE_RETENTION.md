# ScreenRest 무료 Firestore 데이터 정리 정책

## 목표

ScreenRest는 Firebase의 무료 Spark 요금제를 유지하면서 오래된 연결 코드,
잠금 해제 요청, 원격 명령이 계속 쌓이는 문제를 줄입니다.

다음 유료 기능은 사용하지 않습니다.

- Firestore TTL 정책
- Cloud Functions
- Cloud Scheduler
- 서버 기반 일괄 삭제 작업
- Blaze 요금제

## `expiresAt` 필드의 의미

연결 코드 문서의 `expiresAt`은 계속 사용합니다. 이 필드는 유료 TTL 삭제를
위한 것이 아니라, Firestore 보안 규칙이 연결 코드의 유효기간을 확인하기
위한 일반 Timestamp 필드입니다.

따라서 Firebase Console에서 `expiresAt`을 TTL 정책으로 등록하면 안 됩니다.

## 앱에서 수행하는 무료 정리 방식

### 이전 연결 코드 정리

- 자녀 기기에서 새 연결 코드를 생성할 때 직전 연결 코드를 함께 전달합니다.
- 새 코드가 정상적으로 저장된 후 이전 코드가 다른 코드라면 삭제를
  시도합니다.
- 이전 코드 삭제에 실패해도 새 연결 코드 생성과 일반 연결 기능은
  실패 처리하지 않습니다.
- 이전 코드는 같은 익명 자녀 UID가 소유한 경우에만 보안 규칙상 삭제할
  수 있습니다.

### 오래된 요청과 명령 정리

- 정리 작업은 부모 기기가 아니라 자녀 기기에서만 수행합니다.
- 정상적인 원격 동기화가 성공한 뒤에만 정리를 시도합니다.
- 정리는 기기별로 최대 3일에 한 번만 실행합니다.
- 생성된 지 7일이 지난 `unlock_requests` 문서를 한 번에 최대 20개
  삭제합니다.
- 생성된 지 7일이 지난 `remote_commands` 문서를 한 번에 최대 20개
  삭제합니다.
- 한 번에 대량으로 읽거나 삭제하지 않으므로 무료 할당량이 갑자기
  소진될 위험을 줄입니다.

정리가 3일 간격으로 실행되므로 정상적인 온라인 기기에서는 문서가 대략
7일에서 10일 동안 보관됩니다. 기기가 오랫동안 오프라인이면 다음 정상
동기화가 실행될 때까지 원격 기록이 유지됩니다.

## 정리 실패 처리

무료 데이터 정리는 앱의 핵심 기능이 아닌 유지 관리 작업입니다.

- 네트워크 오류가 발생해도 앱 사용을 중단하지 않습니다.
- 정리 권한이 없어도 부모·자녀 동기화를 오프라인으로 표시하지 않습니다.
- 정리 실패 때문에 추가 시간 요청이나 승인 기능을 실패 처리하지 않습니다.
- 일시적인 네트워크 오류는 사용자에게 불필요한 오류 메시지를 표시하지
  않고 다음 정리 주기에서 다시 시도합니다.
- 규칙 오류처럼 재시도로 해결되지 않는 실패는 진단을 위해 이벤트 로그에
  기록합니다.

## 읽기 사용량 절감 장치

- Firestore 실시간 Listener는 최근 문서 30개로 제한합니다.
- 부모 기기는 자신에게 필요하지 않은 `remote_commands` Listener를
  등록하지 않습니다.
- 자녀 기기는 로컬에 남아 있는 Pending 요청만 문서 ID로 직접 확인합니다.
- 원격 명령은 마지막으로 확인한 `timestampMillis` 이후만 조회합니다.
- 블록 화면에서는 전체 컬렉션을 다시 읽지 않고 현재 요청 문서와 같은 ID의
  명령 문서만 직접 확인합니다.
- 거절된 요청은 사용되지 않는 원격 명령 문서를 생성하지 않습니다.
- 유지 관리 정리는 3일마다 제한된 쿼리 두 개만 사용합니다.

## 기존 데이터 처리

업데이트된 앱과 보안 규칙을 적용하면 현재 연결된 자녀 기기의 오래된
요청과 명령은 첫 정상 동기화부터 순차적으로 정리됩니다.

한 번에 컬렉션별 20개만 처리하므로 오래된 데이터가 많다면 여러 정리
주기에 걸쳐 삭제됩니다.

다음 데이터는 앱에서 자동으로 삭제할 수 없습니다.

- 앱 삭제 또는 데이터 초기화로 익명 인증 UID가 바뀐 자녀의 문서
- 더 이상 접근할 수 없는 과거 테스트 자녀 문서와 하위 컬렉션
- 현재 기기에 저장되지 않은 오래된 연결 코드

이런 고립 데이터가 테스트 과정에서 많이 생성됐다면 Firebase Console에서
관리자가 한 번 수동으로 삭제합니다. Firestore에서 부모 문서를 삭제해도
하위 컬렉션이 자동으로 삭제되지 않을 수 있으므로 `unlock_requests`와
`remote_commands`도 함께 확인해야 합니다.

## Firebase Console에서 할 일

1. Firebase Console에서 **Firestore Database > 규칙**으로 이동합니다.
2. `docs/FIRESTORE_RULES.md`의 `현재 최종 규칙` 전체를 붙여 넣습니다.
3. **게시**를 누릅니다.
4. TTL 정책은 생성하지 않습니다.
5. Google Cloud 결제 계정이나 Blaze 요금제를 연결하지 않습니다.

추가 색인 생성은 필요하지 않습니다. 정리 쿼리는 단일 숫자 필드인
`createdAtMillis`와 `timestampMillis`만 사용하므로 Firestore의 기본
단일 필드 색인을 사용합니다.

## 출시 전 확인 항목

- 새 연결 코드를 만들었을 때 이전 코드가 삭제되는지 확인합니다.
- 7일이 지난 테스트 요청과 명령이 있는 경우 자녀 기기에서 동기화한 뒤
  최대 20개씩 삭제되는지 확인합니다.
- 규칙을 적용하지 않은 상태에서도 정리 실패로 앱 동기화 전체가 실패
  표시되지 않는지 확인합니다.
- Firebase Console의 Firestore 사용량 화면에서 읽기, 쓰기, 삭제,
  저장 용량을 확인합니다.
- 초기 배포는 소규모로 진행하고 가족 한 그룹당 일일 읽기 횟수를
  관찰합니다.
