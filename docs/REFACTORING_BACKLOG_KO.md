# 유지보수 리팩토링 작업 목록

상태: 1차 구조 분리 및 빌드 검증 완료, 실기기 회귀 검증 대기 — 기준 커밋 `ce0b65d`

## 목표와 원칙

- 기존 차단 정책, 고행 모드, 사용 시간 집계, 부모·자녀 동기화의 동작을 임의로 변경하지 않는다.
- 한 번에 전면 재작성하지 않고, 테스트를 확보한 뒤 기능 단위로 분리한다.
- 리팩토링과 새 기능·Firestore 스키마 변경을 같은 변경 묶음에 섞지 않는다.
- 각 단계마다 변경 전후 빌드·테스트 결과와 실기기 회귀 결과를 기록한다.

## 착수 조건

1. 사용자가 현재 소스와 문서를 검토해 수동 커밋을 완료한다. 키 파일, 빌드 오류 로그, 임시 파일은 커밋 대상에서 제외한다.
2. 기준 커밋과 당시 빌드·테스트 상태를 기록한다. 기준 커밋 `ce0b65d`에서 `compileDebugKotlin`은 통과했고 단위 테스트 97개 중 1개(`SafetyGateTest.allowOnlyMode_blocksUnrelatedPackageButAllowsPhoneFamily`)가 실패했다. 해당 실패는 리팩토링 전부터 존재한다.
3. 부모·자녀 각 기기의 주요 정책 설정과 차단 결과를 회귀 점검 기준으로 남긴다.

## 순차 작업

현재 완료된 1차 분리: 가족 탭의 로컬·원격 사용 현황 카드와 보조 UI를 각각 `FamilyLocalUsageCard.kt`, `FamilyRemoteUsageCard.kt`로 이동했다. 표시·상태·콜백 로직은 그대로 유지했으며, 이동 후 Kotlin 컴파일과 `assembleDebug` 통과 및 단위 테스트 결과(97개 중 동일한 1개 실패)를 확인했다. 실기기 UI·성능 비교는 아직 하지 않았다. 나머지 화면과 정책·서비스 분리는 아직 진행하지 않았다.

2차 분리: 자녀 기기의 앱 사용 현황 공유 동의 카드와 가족 기기 동기화 카드를 `FamilyDeviceCards.kt`로 이동했다. 동의 절차, 새로고침 버튼의 활성 조건, 동기화 표시 문구는 변경하지 않았다. Kotlin 컴파일과 `assembleDebug`가 통과했으며, 단위 테스트는 이전과 동일하게 97개 중 기존 1개가 실패했다. 실기기 UI·성능 비교는 아직 하지 않았다.

3차 분리: 자녀의 요청 이력·가족 관리 진입 UI를 `FamilyRequestCards.kt`로, 자녀용 가족 대시보드를 `FamilyChildDashboard.kt`로 이동했다. PIN, 승인, 차단 정책 계산은 건드리지 않았다. Kotlin 컴파일과 `assembleDebug`가 통과했고, 단위 테스트는 이전과 동일하게 97개 중 기존 1개가 실패했다. 실기기 UI·성능 비교는 아직 하지 않았다.

4차 분리: 부모용 가족 대시보드를 `FamilyParentDashboard.kt`로 이동했다. 기준 커밋의 원본 함수 본문과 이동 후 본문이 접근 제한자 외에는 동일함을 확인했다. Kotlin 컴파일과 `assembleDebug`가 통과했고, 단위 테스트는 이전과 동일하게 97개 중 기존 1개가 실패했다. 실기기 UI·성능 비교는 아직 하지 않았다.

5차 분리: 가족 탭 진입·관리 화면과 오늘·규칙·통계·더보기 최상위 화면을 기능별 파일로 이동했다. 정책 초안 계산, 스케줄·앱 그룹 정책 계산, 감시 서비스의 차단 판정 표시 변환도 각각 별도 파일로 분리했다. 저장 스키마와 정책 우선순위는 변경하지 않았다. 최종 통합 `compileDebugKotlin`과 `assembleDebug`가 통과했다. 기존 실패는 허용 앱과 제한 없는 앱의 의미가 섞인 테스트 기대값 문제로 확인해 프로덕션 로직 변경 없이 수정했으며, 현재 단위 테스트 97개가 모두 통과한다. 자세한 내용은 `REFACTORING_REPORT_KO.md`를 참고한다.

### 1. 핵심 동작을 테스트로 고정

- 5가지 정책의 중복 적용, 필수 허용·제한 없는 앱, 고행 1·2·3단계의 판정 테스트를 정리한다.
- 부모 즉시 차단의 발행·4시간 유지·앱 재실행 후 상태 복원·종료·오프라인 재연결을 검증한다.
- 화면 켜짐·앱 전환·자정·재부팅 경계의 사용 시간 집계를 검증한다.
- Firebase/FCM 실패, 지연, 중복 이벤트를 테스트할 수 있는 경계를 만든다.

### 2. 화면을 기능별 파일로 분리

- `MainActivity.kt`의 오늘·규칙·통계·가족·더보기 화면을 순서대로 분리한다.
- 화면 이동과 저장 프로세스는 유지하고, 화면별 상태와 이벤트 전달 범위를 줄인다.
- `BlockedActivity`와 서비스 오버레이의 공통 문구·버튼 상태를 한 모델에서 생성한다.

### 3. 정책·저장·원격 동기화 책임 분리

- `SettingsRepository.kt`의 정책 모델/계산, DataStore 직렬화, 가족 연결·원격 명령을 분리한다.
- `SafeModeViewModel.kt`의 사용량, 정책 편집, 가족 동기화 상태를 기능 단위로 분리한다.
- `UsageMonitorForegroundService.kt`에서 감시·판정과 블록 UI 조립을 분리한다.
- 시각 의존 정책에 주입 가능한 시계를 사용해 만료·자정 테스트를 결정적으로 만든다.

### 4. 자동 검증과 문서 갱신

- 주요 부모·자녀 흐름의 계측/통합 테스트와 빌드·단위 테스트 자동 실행을 추가한다.
- 실제 코드와 다른 `PROJECT.md`, `ARCHITECTURE.md`의 오래된 상태 설명을 갱신한다.
- Android 11~16, 오프라인, 프로세스 종료, 재부팅, 화면 꺼짐을 실기기 점검표로 확인한다.

## 완료 기준

- 리팩토링 전후 동일 설정에서 정책 판정·집계·블록 화면·해제 결과가 같다.
- 부모 기기가 자녀의 활성 즉시 차단을 읽지 못할 때 이를 ‘차단 없음’으로 표시하지 않는다.
- 기존 단위 테스트와 추가한 핵심 흐름 테스트가 통과하고, 실기기 회귀 결과가 기록된다.
- 큰 파일의 분리는 책임 경계를 기준으로 이루어지며, 새로운 거대 공용 파일을 만들지 않는다.
