# 폰 쉼 상용화 리디자인 설계 기준

작성일: 2026-09-11  
상태: 4단계 오늘·규칙 탭 구현 완료·기기 시각 검증 대기  
기준 시안: `neutral-family-rhythm`, `neutral-family-rhythm-revised`

## 1. 이번 리디자인의 목표

이번 작업은 기존 기능을 새로 해석하는 작업이 아니라, 이미 동작하는 기능과 정책을 유지한 채 사용자가 더 빠르고 정확하게 이해할 수 있도록 화면 구조와 시각 체계를 바꾸는 작업이다.

우선순위는 다음과 같다.

1. 정책 엔진, 사용량 집계, 고행 모드, 부모·자녀 연결, FCM, 관리 PIN, Emergency Pass의 의미와 동작을 바꾸지 않는다.
2. 사용자가 현재 상태, 적용 중인 규칙, 다음 행동을 한눈에 이해할 수 있게 한다.
3. 기존에 정상 동작하는 기능과 예외 처리를 빠뜨리지 않는다.
4. 시안의 시각 언어를 일부만 흉내 내지 않고 화면 밀도, 여백, 타이포그래피, 색, 아이콘, 컴포넌트 상태까지 일관되게 옮긴다.
5. 구현은 화면별로 나누고, 각 단계마다 시안과 실제 화면을 같은 크기로 비교한 뒤 다음 단계로 넘어간다.

## 2. 변경하지 않는 기능 계약

다음 항목은 UI 리디자인 과정에서 수정하지 않는다.

- 사용량 집계 및 30일 기록의 기존 계산 흐름
- 차단 우선순위와 정책 충돌 해석
- 요일별 제한, 앱 그룹, 앱별 제한, 스케줄, 허용 앱만, 제한 없는 앱의 정책 의미
- 앱 그룹 중복 방지와 연관 앱 처리
- 임시 허용, 오늘만 해제, 부모 승인 요청
- 고행 1·2·3단계의 시작, 종료, 숙고 시간, 잠금 조건
- 관리 PIN 검증 규칙
- Emergency Pass의 7일 공용 주기, 현재 앱 한정 예외, 만료 기준
- 안전 복구가 고행 3단계를 우회할 수 없다는 규칙
- 부모·자녀 연결, 푸시 토큰, FCM, Firestore 문서 형식
- 권한 점검과 포그라운드 감시 서비스

다만 통계의 ‘일별 목표 달성’은 현재 기록에 날짜별 목표 스냅샷이 없으므로 별도 데이터 확장이 필요하다. 이 변경은 화면 리디자인과 분리하여 검증한다.

## 3. 새 정보 구조

현재 6개 하단 탭을 다음 5개 탭으로 재구성한다.

| 새 탭 | 현재 기능 출처 | 책임 |
|---|---|---|
| 오늘 | 개요 | 현재 상태, 오늘 사용량, 적용 중인 규칙, 긴급 요청 |
| 규칙 | 시간 + 차단 | 모든 정책의 설정과 실제 적용 결과 |
| 통계 | 통계 | 7일·30일 흐름, 날짜별 목표 달성, 앱·그룹 사용량 |
| 가족 | 설정 > 부모 관리 | 역할, 프로필, 연결, 자녀 현황, 요청, 원격 제어 |
| 더보기 | 안전 + 나머지 설정 | 보호 상태, PIN, Emergency Pass 정보, 권한, 알림, 언어, 계정, 진단 |

‘저장’은 화면 목적지가 아니므로 하단 탭에 두지 않는다. 정책 편집 중일 때만 모든 탭 위에 공통 저장 바를 표시한다.

## 4. 공통 디자인 시스템

### 색상

- 배경: 따뜻한 미색에 가까운 아주 밝은 중립색
- 기본 텍스트: 짙은 네이비
- 주요 행동과 선택: 코발트 블루
- 정상·연결·목표 이내: 청록
- 요청·주의·임박: 오렌지
- 차단·초과·삭제: 코럴 레드
- 고행 단계: 기존 단계 색의 의미를 유지하되 채도와 대비를 통일

### 형태와 밀도

- 본문 14~16sp, 보조문 13~14sp, 큰 상태 숫자만 제한적으로 확대
- 기본 터치 영역 최소 48dp
- 카드 안의 중첩 카드를 피하고, 같은 그룹은 구분선과 여백으로 나눈다.
- 주요 카드 모서리는 20~24dp, 행과 버튼은 14~18dp로 통일한다.
- 그림자보다 배경색 차이와 1dp 윤곽선을 먼저 사용한다.
- 아이콘은 동일한 굵기의 선형 아이콘으로 통일하고, 상태색은 아이콘과 핵심 숫자에만 사용한다.

### 반응형

- 휴대전화 세로 화면을 기준으로 먼저 완성한다.
- 가로 화면과 태블릿은 기존 `AdaptiveTwoPane` 동작을 유지하되, 카드 폭과 읽기 순서가 달라지지 않게 한다.
- 작은 화면에서는 텍스트를 생략하지 않고 행을 세로로 재배치한다.

## 5. 오늘 탭

### 권장 구성

1. 상단: 폰 쉼 브랜드 또는 화면 제목 + 조건부 프로필 선택기
2. 현재 상태 헤드라인
3. 오늘 사용량과 남은 시간
4. 현재 적용 중인 규칙
5. 부모가 처리해야 할 최신 승인 요청 또는 자녀가 보낸 요청 상태
6. 오늘 많이 사용한 앱 목록

### 상단 프로필 노출 규칙

- Google 로그인 계정 이름이 있으면 표시한다.
- 가족 탭에 저장한 프로필 이름이 있으면 이를 우선 표시한다.
- 둘 다 없으면 프로필 영역 자체를 숨긴다.
- 부모 기기에서 여러 자녀가 연결되면 자녀 선택기로 동작한다.
- 자녀 기기나 미연결 기기에서는 불필요한 선택 화살표를 표시하지 않는다.

### 현재 상태 문구

상태는 정책 이름을 나열하기보다 사용자가 지금 무엇을 할 수 있는지 설명한다.

| 조건 | 대표 문구 | 보조 문구 |
|---|---|---|
| 권한 또는 감시 서비스 문제 | 보호 상태 확인 필요 | 권한 또는 서비스 1개 확인 필요 |
| 오늘 전체 제한 도달 | 오늘 사용 시간이 끝났어요 | 다음 사용 가능 시각 또는 부모 요청 가능 여부 |
| 앱이 개별·그룹 제한에 임박 | 사용 시간이 얼마 남지 않았어요 | 가장 먼저 끝나는 앱 또는 그룹과 남은 시간 |
| 활성 스케줄 | `{스케줄명}` 적용 중 | 종료 시각과 허용 앱 수 |
| 허용 앱만 활성 | 허용된 앱만 사용할 수 있어요 | 허용 앱 수와 다음 변경 정보 |
| 시간 제한만 활성 | 현재 자유 시간 | 오늘 사용량과 가장 먼저 끝나는 제한 |
| 활성 정책 없음 | 자유롭게 사용할 수 있어요 | 설정된 제한 없음 |
| 사용량 새로고침 중 | 사용량 업데이트 중 | 마지막 정상 기록은 그대로 유지 |

고행 단계는 대표 상태를 덮지 않고 해당 규칙 행과 상태 카드에 단계 배지로 표시한다.

### 규칙별 표시

- 요일별: `42분 사용 · 1시간 18분 남음`
- 앱 그룹: `게임 · 18분 남음`
- 앱별: `YouTube · 12분 남음`
- 스케줄: `공부 시간 · 21:00 종료`
- 허용 앱만: `허용 앱 6개`
- 제한 없는 앱과 임시 허용: 필요할 때만 별도 보조 행으로 표시
- 비활성 정책은 오늘 탭에 표시하지 않는다.

### 승인 요청 위치

- 부모 기기: 최신 미처리 요청 한 건을 오늘 탭의 사용량 아래에 두는 것이 적절하다. 빠른 판단이 필요한 항목이기 때문이다.
- 전체 요청과 처리 기록은 가족 탭에서 본다.
- 자녀 기기: 부모에게 보낸 요청의 `전송됨`, `재시도 중`, `승인`, `거절`, `만료` 상태만 표시한다.
- 미연결 기기: 요청 영역을 표시하지 않는다.

## 6. 규칙 탭

### 카테고리 명칭 제안

기존 `시간 제한`은 **사용 시간**, 기존 `실행 범위`는 **사용 가능 앱**으로 변경하는 안을 권장한다.

- 사용 시간: 요일별 제한, 앱 그룹, 앱별 제한
- 사용 가능 앱: 스케줄, 허용 앱만, 제한 없는 앱

이 명칭은 정책 구현 방식이 아니라 사용자가 얻는 결과를 설명한다.

### 화면 구성

1. 상단 `현재 적용 결과`
2. 가장 먼저 끝나는 제한 또는 현재 차단 원인
3. `사용 시간` 정책 목록
4. `사용 가능 앱` 정책 목록

각 정책은 한 개의 확장 행으로 만든다.

- 접힘: 아이콘, 정책명, 요약, 활성·설정됨·고행 단계 상태
- 펼침: 현재 설정 전체, 검색과 목록, 도움말, 활성 스위치, 편집 행동
- 활성 스위치가 필요한 정책은 펼친 영역 안에 둔다.
- 단순히 값만 설정하는 앱 그룹·앱별 제한은 `설정됨`과 적용 개수를 표시한다.
- 비활성 스케줄은 다른 화면에서 `스케줄 차단`으로 표시하지 않는다.
- 허용 앱만과 다른 시간 정책의 관계는 앱 행에 `허용됨`, `허용 앱만에서 차단`, `제한 없음`으로 동기화해 표시한다.

### 누락 방지 항목

- 00시간 00분과 제한 없음의 구분
- 요일별 활성 스위치와 값 보존
- 앱 그룹·앱별 제한의 적용 요일
- 앱 그룹 중복 선택 방지와 소속 그룹명
- 앱 검색과 선택 확인 팝업, 스크롤 위치 유지
- 스케줄별 허용 앱, 검색, 고행 단계, 활성 상태
- 허용 앱만의 선택·필수·제한 없음·임시 허용 상태
- 제한 없는 앱 검색과 연관 앱 처리
- 모든 고행 단계 편집·잠금·종료 상태
- 임시 허용 취소와 정정
- 정책 설명 물음표

## 7. 통계 탭

### 시각 구성

- 기준 시안과 거의 동일하게 7일·30일 전환, 평균, 전 기간 대비 변화, 일별 막대, 목표 달성 일수, 많이 사용한 앱 순서로 구성한다.
- 일별 막대는 목표 이내 청록, 임박 오렌지, 초과 코럴, 선택일 코발트로 표시한다.
- 많이 사용한 앱은 3개로 제한하지 않는다. 현재처럼 내부 스크롤 또는 `전체 보기` 확장으로 더 볼 수 있게 한다.
- 앱 그룹 통계와 상세 일별 통계는 아래 확장 영역에 유지한다.

### 날짜별 목표 계산

고정된 한 개 목표선으로 7일 전체를 판단하지 않는다. 각 날짜에 실제 적용된 요일별 목표를 기준으로 그날의 달성 여부를 계산한다.

현재 `usage_history_v1`에는 앱별 사용량만 있고 그날의 목표가 기록되지 않는다. 따라서 다음을 별도 구현한다.

1. 날짜별 `dailyGoalMinutes` 스냅샷을 사용 기록과 함께 저장한다.
2. 그날 제한이 없었던 경우 `목표 없음`으로 기록한다.
3. 목표가 있었던 날만 `목표 이내/초과` 일수의 분모에 포함한다.
4. 기존 과거 기록에는 목표 스냅샷이 없으므로 임의로 현재 설정을 적용하지 않는다.
5. 과거 목표 미기록일은 그래프 사용량에는 포함하고 목표 달성 집계에서는 제외한다.

이 데이터 변경은 UI 리디자인과 분리된 작은 마이그레이션으로 구현한다.

## 8. 가족 탭

### 역할별 첫 화면

#### 부모 기기

1. 연결 상태와 마지막 동기화
2. 자녀 선택기
3. 선택한 자녀의 오늘 사용량, 남은 시간, 현재 상태
4. 활성 규칙 요약
5. 즉시 차단 행동
6. 미처리 승인 요청
7. 가족 및 기기 관리 진입

#### 자녀 기기

1. 연결된 부모와 연결 상태
2. 내 프로필 및 기기 이름
3. 연결 코드 생성
4. 보낸 요청 상태
5. 동기화와 연결 해제

#### 미연결 기기

1. 부모 기기/자녀 기기 역할 선택
2. 프로필 이름
3. 역할에 따른 Google 로그인 또는 연결 코드 생성·입력
4. 연결 과정 안내

### 현재 부모 관리에서 반드시 이관할 항목

- 부모/자녀 기기 역할 선택과 관리 PIN 확인
- 프로필 이름 저장 및 저장 완료 상태 유지
- 자녀 연결 코드 생성과 PIN 확인
- 부모 기기의 연결 코드 등록과 PIN 확인
- 부모 Google 로그인과 복구 가능 상태
- 연결된 부모·자녀 기기 목록
- 연결 해제, 동기화
- 자녀 요청 승인: 시간 추가, 오늘만 해제, 거절
- 요청 알림 준비 상태, 마지막 성공, 최근 오류
- 기기 연결 ID와 마지막 동기화
- 계정 및 클라우드 데이터 삭제 진입

계정 자체와 데이터 삭제는 더보기의 `Google 계정` 상세에서도 접근할 수 있지만, 실제 가족 연결과 기기 관리는 가족 탭을 단일 기준 화면으로 삼는다.

### 즉시 차단

시안에는 `지금 차단` 버튼과 현재 상태를 넣는다. 실제 동작은 새로운 원격 명령, 해제 조건, 실패·오프라인 처리, 고행 단계와의 관계를 정의해야 하므로 기존 UI 리디자인과 별도 기능 단계로 분리한다.

구현 전에 다음 정책을 확정해야 한다.

- 즉시 차단 대상: 전체 앱 또는 선택 앱
- 해제 기준: 부모가 해제할 때까지, 지정 시간, 오늘 자정 중 하나
- 자녀 기기가 오프라인일 때 예약 명령으로 남길지 여부
- 기존 고행 3단계보다 강한지, 단순한 새 차단 원인인지

## 9. 더보기 탭 이관 보고

더보기 첫 화면은 기준 시안의 구조를 그대로 사용하되, 다음처럼 현재 기능을 배치한다.

### 상단 보호 상태

`정상 작동 중/확인 필요` 카드와 `상태 확인` 버튼을 둔다. 버튼은 별도 **보호 상태** 화면을 연다.

보호 상태 화면으로 이동하는 현재 기능:

- 안전 모드 상태
- 정책 적용 상태
- 차단 준비 상태
- 사용정보 접근, 오버레이, 알림, 알림 접근, 정확한 알람 권한
- 감시 서비스 상태
- 시스템 건강 상태
- 자동 복구 상태
- 상세 진단
- 차단 판단 시뮬레이션
- 차단 화면 미리보기
- 안전 복구

### 보호 및 보안

- `관리 PIN`: 현재 PIN 변경 기능과 설명
- `긴급 사용권`: Emergency Pass 상태와 설명만 보여주는 새 상세 화면
- `권한 및 작동 상태`: 상단의 보호 상태 화면과 같은 목적지

Emergency Pass 상세 화면에는 다음만 표시한다.

- 사용 가능 또는 사용 완료
- 다음 사용 가능 시각
- 7일 동안 모든 고행 3단계에서 한 번이라는 규칙
- 현재 앱에만 적용되고 현재 차단 정책 종료 시 만료된다는 규칙
- 사용은 블록 화면에서만 가능하다는 안내

더보기에서 Emergency Pass를 미리 사용하거나 충전·초기화하는 버튼은 만들지 않는다.

### 앱 설정

- `알림`: 경고 알림, 초과 알림
- `언어`: 한국어, English
- `화면 및 접근성`: 글자 크기·테마 항목은 현재 구현이 없으므로 1차 버전에서는 만들지 않고, 권한 바로가기를 이 이름 아래 넣지 않는다.

### 계정 및 지원

- `Google 계정`: 로그인 상태, 계정 복구, 계정 및 클라우드 데이터 삭제
- `도움말`: 다섯 정책, 고행, 부모 연결, Emergency Pass 설명
- `진단 정보`: 이벤트 로그, 진단 정보 생성·보내기

### 중복 제거 원칙

- 가족 탭: 관계, 역할, 연결, 자녀 상태, 요청, 원격 행동
- 더보기: 계정, 앱 보안, 권한, 환경설정, 진단
- 같은 기능을 두 화면에서 서로 다르게 편집하지 않는다.

## 10. 안전 탭 처리 제안

하단의 안전 탭은 제거하고 더보기 상단의 `상태 확인` 안으로 이동하는 방안을 권장한다.

다만 기능 자체를 없애거나 앱 시작 시 임의로 켜지는 방식으로 바꾸지 않는다.

- `안전 모드 OFF`: 차단이 허용되는 정상 보호 상태라는 현재 의미가 혼동되므로, 사용자 문구를 `보호 작동 중`으로 바꾼다.
- `안전 모드 ON`: `보호 일시 중지`로 표시한다. 정책은 보존되지만 차단은 중지된다는 설명을 붙인다.
- `정책 적용 ON/OFF`: `규칙 적용`으로 이름을 바꾸고 보호 상태 상세의 고급 제어에 둔다.
- 정책 적용을 끄거나 보호를 일시 중지하는 동작은 현재처럼 관리 PIN 확인을 유지한다.
- 필수 권한이 없는 상태를 자동으로 보호 작동 중이라고 표시하지 않는다.
- 앱 실행만으로 사용자 동의 없이 정책 적용을 자동 활성화하지 않는다.

이 안은 사용자가 `Safe Mode OFF`를 위험 상태로 오해하는 문제를 줄이면서 기존 상태값과 동작은 그대로 보존한다.

## 11. 블록 화면

### 시각 방향

- 기준 시안의 어두운 전체 배경, 중앙 상태 아이콘, 큰 차단 사유, 밝은 행동 패널을 유지한다.
- 파스텔 전체 배경 대신 짙은 네이비 기반에 모드별 기본색에 가까운 강한 강조색을 사용한다.
- 배경 전체를 색칠하기보다 아이콘 광원, 상단 배지, 강조선, 핵심 숫자에 모드 색을 사용한다.

| 차단 원인 | 강조색 |
|---|---|
| 요일별/하루 전체 | 코럴 레드 |
| 앱 그룹 | 앰버 오렌지 |
| 앱별 제한 | 코발트 블루 |
| 스케줄 | 인디고 |
| 허용 앱만 | 청록 |
| 고행 | 단계별 기존 의미색 |

### 반드시 유지할 내용과 행동

- 차단 원인과 대상 앱
- 사용 시간, 제한 시간, 다시 사용할 수 있는 시각
- 고행 단계와 단계별 설명
- 고행 1단계 숙고 카운트다운, 5분 임시 허용, 사용 종료 안내
- 고행 2단계 숙고와 관리 PIN 종료
- 고행 3단계 Emergency Pass 가능 여부와 다음 사용 가능 시각
- 요청 전송됨, 재시도 중, 실패 상태
- 관리 PIN 확인 팝업과 Emergency Pass 최종 경고
- 미리보기 상태와 닫기

일반 차단에서 사용하는 버튼 이름은 현재 앱의 문구를 그대로 사용한다.

- 시간 추가
- 오늘만 해제
- 안전 복구
- 폰 쉼 열기
- 홈으로
- 자녀 기기이면서 부모 연결이 있을 때만 부모에게 요청

고행 단계에서는 기존 정책에 따라 버튼이 숨겨지거나 `2분 숙고 / 5분 허용`, `30분 숙고 / 관리 PIN으로 종료`, `Emergency Pass 사용`으로 대체되는 현재 조건을 유지한다.

### 구현상 중요 사항

블록 UI는 `BlockedActivity`와 포그라운드 서비스 오버레이 두 경로가 있다. 두 화면을 각각 따로 디자인하지 않고 하나의 `BlockScreenUiModel`과 공통 색·간격·문구 규칙을 공유하게 해야 한다. 한쪽만 바꾸면 기기와 상황에 따라 서로 다른 블록 화면이 보이는 문제가 다시 생긴다.

## 12. 저장 방식

정책은 자녀 사용에 직접 영향을 주고 관리 PIN 확인이 필요하므로 자동 저장보다 현재의 명시적 저장 방식을 유지하는 것이 안전하다.

권장 흐름:

1. 편집 전에는 저장 바를 숨긴다.
2. 변경이 생기면 하단 탐색 바로 위에 붉은 계열의 고정 저장 바를 표시한다.
3. 문구: `변경사항이 있습니다 · 저장해야 적용됩니다`
4. 행동: `저장`, 보조 행동 `변경 취소`
5. 저장을 누르면 변경 요약과 관리 PIN 확인을 한 화면에 표시한다.
6. 저장 성공 후 `저장됨` 상태를 잠시 보여주고 저장 바를 닫는다.
7. 탭 이동 시 초안은 유지한다.
8. 앱 종료 또는 뒤로 가기로 초안을 잃을 때만 이탈 경고를 표시한다.

프로필 이름, 언어, 알림처럼 정책 엔진과 무관한 값은 해당 화면에서 즉시 저장하고 완료 상태를 표시한다. 정책 저장 바와 섞지 않는다.

## 13. 구현 구조

거대한 `MainActivity.kt`에 새 UI를 계속 추가하지 않는다. 기능 콜백은 유지하고 화면을 다음 단위로 분리한다.

- `ui/designsystem`: 색, 타이포그래피, 간격, 아이콘 크기, 공통 상태 배지
- `ui/navigation`: 5개 탭 셸과 조건부 저장 바
- `ui/today`: 오늘 화면과 상태 변환기
- `ui/rules`: 정책 요약, 확장 정책 행, 기존 편집 컴포넌트 연결
- `ui/statistics`: 7일·30일 그래프와 앱 목록
- `ui/family`: 역할별 가족 대시보드와 기존 부모 관리 기능
- `ui/more`: 더보기 메뉴와 세부 화면
- `ui/protection`: 기존 안전 탭의 보호 상태·진단·복구
- `ui/blocking`: Activity와 오버레이가 공유하는 블록 화면 표현 모델

화면은 `SafeModeUiState` 원본을 직접 재해석하지 않고 화면별 UI 모델 변환기를 둔다. 그래야 표시와 정책 판단이 서로 뒤섞이지 않는다.

## 14. 단계별 구현 계획

현재 진행 상태:

- 1단계 완료: 공통 색상·타이포그래피·간격·모서리·공통 컴포넌트와 기능 보존 기준 작성
- 2단계 완료: `오늘·규칙·통계·가족·더보기` 5탭 셸과 메뉴형 더보기 첫 화면 적용
- 안전 탭 기능 이관 완료: 보호 상태 상세에서 보호 일시 중지, 규칙 적용, 권한, 진단, 미리보기와 안전 복구 제공
- 설정 이관 완료: 관리 PIN, 긴급 사용권, 알림, 언어, Google 계정, 도움말과 진단 정보를 각각의 상세 화면으로 분리
- 3단계 완료: 부모·자녀·미연결 상태에 따른 가족 첫 화면과 기존 가족 및 기기 관리 상세 화면 구성
- 부모 화면의 승인 요청과 자녀 사용 현황은 실데이터를 사용하고 즉시 차단은 실제 원격 상태를 표시한다. 원격 규칙 변경은 출시 범위에서 제외하며 진입점이나 준비 중 표시를 노출하지 않는다.
- 4단계 완료: 오늘 탭을 현재 상태, 전체 사용량, 적용 중 규칙, 가족 요청, 많이 사용한 앱 순서로 재구성
- 오늘 상단 브랜드에는 실제 앱 아이콘을 사용하고, 많이 사용한 앱은 상위 5개를 유지하되 나머지는 `통계` 탭으로 바로 이동해 확인하도록 연결
- 4단계 완료: 규칙 탭에 실제 적용 결과를 먼저 표시하고 시간 제한과 실행 범위의 다섯 정책을 한 화면에서 접고 펼칠 수 있도록 통합
- 규칙 카드는 한 줄 설명과 접힌 상태의 활성 여부·설정 개수를 표시하며, 활성화 스위치는 카드를 펼쳤을 때만 노출
- 앱 그룹과 스케줄은 목록의 항목별 활성 스위치로 제어한다. 새 항목은 꺼진 상태로 만들고, 기존 앱 그룹은 활성·기존 스케줄은 종전 전체 스위치 상태를 각각 이어받는다. 고행 모드가 설정된 항목은 해제 또는 종료 전까지 끌 수 없다.
- 기존 정책 저장 바, 관리 PIN 확인, 고행 설정, 검색과 앱 선택 동작은 유지
- 새 설치에서는 다섯 규칙 편집 영역을 접힌 상태로 시작하며 사용자의 이후 펼침 상태는 기존 방식대로 보존
- 5단계 완료: 통계 탭을 7일·30일 전환, 기간 평균과 이전 기간 비교, 일별 막대, 목표 달성 결과, 스크롤 가능한 많이 사용한 앱 순서로 재구성
- 일별 막대 색은 목표 이내(청록), 목표 임박 85~100%(주황), 목표 초과(코랄), 목표·기록 없음(회색)으로 고정하고 범례를 표시하며, 오늘은 막대색 대신 날짜·사용량 글자색으로 구분
- 오늘 탭의 앱 아이콘은 원형으로 잘라 표시한다.
- 날짜별 목표 스냅샷을 사용 기록과 분리된 통계 전용 파일로 추가했으며, 과거 목표가 없는 날에는 현재 설정을 소급 적용하지 않음
- 그룹 통계는 기존 기능을 유지하되 기본 화면 길이를 줄이기 위해 필요할 때 펼치는 보조 영역으로 변경
- 다음 작업: 모든 차단 방식에 공통으로 적용되는 블록 화면 재구성

### 0단계 — 결정 확정

- 규칙 카테고리 명칭
- 오늘 상단 브랜드 표시
- 안전 모드와 규칙 적용의 노출 수준
- 즉시 차단의 이번 범위
- 과거 목표 미기록일 처리
- 저장 방식

### 1단계 — 시각 기준과 기능 보존표

- 디자인 토큰과 공통 컴포넌트 작성
- 공통 구현 위치: `app/src/main/java/com/manisykh/screenrest/ui/designsystem`
- 현재 기능을 새 화면 목적지와 1:1로 연결
- 화면별 상태표와 수용 조건 고정
- 코드 동작은 변경하지 않음

### 2단계 — 5탭 셸과 더보기

전환 구현: 더보기의 `화면 구성`에서 새 5탭과 기존 6탭 구성을 선택한다. 기존 구성에서는 시간·차단·안전·설정 화면을 독립된 탭으로 다시 연결하며, 선택값은 기기에 저장한다. 두 구성은 같은 정책 데이터·저장 흐름을 공유한다. 오늘·통계의 이전 시각 디자인을 별도로 복제하는 기능은 포함하지 않는다.

- 새 하단 탐색
- 더보기 첫 화면
- 보호 상태 상세로 기존 안전 화면 이관
- 설정 항목의 목적지만 재배치
- 이 단계에서 정책 편집 기능은 기존 화면을 그대로 연결

### 3단계 — 가족

- 역할별 가족 첫 화면
- 기존 부모 관리 항목 이관
- 승인 요청과 연결 기기 상태
- 즉시 차단은 정책 확정 후 별도 기능 플래그로 추가

### 4단계 — 오늘과 규칙

- 오늘 상태 변환기와 조건부 카드
- 시간·차단 정책을 규칙 탭으로 통합
- 기존 정책 편집 컴포넌트를 확장 행 안에 연결
- 공통 저장 바와 관리 PIN 확인

### 5단계 — 통계

- 시안형 7일·30일 그래프
- 스크롤 가능한 많이 사용한 앱
- 날짜별 목표 스냅샷을 별도 마이그레이션으로 추가

### 6단계 — 블록 화면

- 공통 블록 UI 모델
- Activity와 오버레이를 같은 디자인으로 변경
- 일반·자녀·고행 1·2·3·미리보기 상태별 점검

구현 현황: 공통 색상·차단 유형 배지·어두운 상태 영역·밝은 행동 패널을 두 화면에 적용했다. 버튼의 기존 조건과 PIN 동작은 유지했다. 기기별 화면 및 상호작용 검증은 사용자가 컴파일·설치한 뒤 7단계에서 확인한다.

### 7단계 — 시각 검증과 출시 점검

- 기준 시안과 실제 화면을 동일 크기로 나란히 비교
- 작은 화면, 태블릿, 한국어, 영어, 긴 앱 이름, 큰 글꼴 점검
- 빈 상태, 로딩, 오류, 오프라인, 권한 누락 상태 점검
- TalkBack 읽기 순서, 색 대비, 48dp 터치 영역 점검
- 기존 정책 회귀 검증 체크리스트 작성

사용자가 직접 컴파일과 장시간 기기 검증을 수행하며, 구현 단계에서는 화면별 변경 목록과 짧은 수동 검증 절차를 함께 제공한다.

## 15. 구현 완료 조건

- 기준 시안과 실제 화면의 구조, 여백, 색, 글자 계층, 아이콘 위치가 화면별로 일치한다.
- 현재 기능 보존표의 모든 항목이 새 화면에서 접근 가능하다.
- 비활성 정책이 오늘 또는 다른 정책 목록에서 활성 상태로 잘못 표시되지 않는다.
- 부모·자녀·미연결 역할에 맞지 않는 UI가 노출되지 않는다.
- 정책 변경은 저장 전 적용되지 않고, 저장 후 성공 상태가 명확하다.
- 블록 Activity와 오버레이가 같은 내용과 시각 구조를 사용한다.
- 그래프는 날짜별 목표를 알고 있는 날만 목표 달성 집계에 사용한다.
- 기존의 정상 동작을 바꾸는 데이터·정책 변경이 UI 커밋에 섞이지 않는다.

5. 목표 기록이 없는 기존 날짜는 제안대로 그래프에는 표시하되 목표 달성 일수에서는 제외할 것인가?
6. 정책 저장은 제안한 공통 저장 바와 관리 PIN 흐름으로 유지할 것인가?
